# 页面规划 · Product Hunt 推荐组图

这份文档讲**怎么把榜单变成一组能打的图**。核心:表达优先 — 先想清楚每页让观者懂什么,再填内容。

## 组图结构(封面 + 产品页 × N + 总结)

| 页 | id | 一页一个主张 |
|---|---|---|
| 封面 | `xhs-cover` | 一句话钩子:这一组为什么值得看 |
| 产品页 | `xhs-<rank>` | 该产品凭什么上榜(卖点 + 评价) |
| 总结 | `xhs-summary` | 一句话收尾 + 完整榜单 |

## 文案纪律

### 封面
- **大标题**:≤2 行、单行 ≤8 字。例:「本周 5 个\n值得玩的产品」(用 `\n` 显式断行)。
- **钩子(hook)**:一句话说清取舍,如「少踩坑:从 200+ 里挑出这 5 个真值得装的」。
- 不要罗列所有产品名 — 那是产品页的事。

### 产品页
- **卖点(one-liner)**:一句话,讲「它解决什么、适合谁、和别家差在哪」。
- **AI 评价(review)**:2~3 句,围绕卖点、适用人群、竞品差异,可略带推荐语气。**由 agent 撰写,但不得编造票数/评论/排名数字** — 那些脚本会从 data.json 填真实值。
- 标题/简介/票数/评论/缩略图/链接全部来自真实榜单,不覆盖不造假。

### 总结
- **一句话收尾(title)**:≤2 行、单行 ≤8 字,给整组一个落点。
- **note**:一句话,如「完整 50 名榜单见链接,下期见」。

## 选择风格与主题

- 默认 **Swiss + ikb**(产品/科技内容最贴)。
- 想要「专栏感、慢一点」→ **Editorial + indigo-porcelain**。
- 想要「年轻、活泼」→ Swiss 的 lemon-yellow / lemon-green。
- 一套组图**只选一个风格、一个主题**,不混搭。

## 写 plan.json

agent 把上面这些填进 `plan.json` 交给 `build-deck.mjs`:

```json
{
  "style": "swiss",
  "theme": "ikb",
  "cover":   { "title": "本周 5 个\n值得玩的产品", "hook": "从本周新品里挑出 5 个真值得装的", "countBadge": "05" },
  "products": [
    { "rank": 1, "one-liner": "一句话卖点", "review": "2~3 句 AI 评价" },
    { "rank": 2, "one-liner": "…",         "review": "…" }
  ],
  "summary": { "title": "好产品不难找", "note": "完整榜单见链接,下期见" }
}
```

`rank` 必须对应 `data.json` 里存在的 rank;脚本按 rank 合并真实数据,缺 rank 会跳过并告警。

## 交付前检查

- 每页一句人话能说清「这张在讲什么」。
- 封面钩子不打满产品名;产品页不堆数字。
- 卡上面没有「本期推荐」「制作要求」这类内部腔文案。
- 票数/评论/排名与 data.json 一致。
